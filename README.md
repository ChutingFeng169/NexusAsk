# NexusAsk

> A Streamlit-based **Agentic RAG** application: native tool-calling, real token-by-token streaming, a persistent per-user file Library, cross-conversation memory, semantic cache, and LangSmith tracing — built on a pinned legacy LangChain 0.1.20 stack (no LangGraph).

NexusAsk (formerly DocChat) has evolved from a simple Chroma-vector-store RAG into a full agentic assistant: it calls tools (search the docs / web / Wikipedia / calculate), streams answers live, remembers you across conversations, and keeps every file you've ever uploaded in a personal Library.

---

## Features

- **Native tool-calling agent** over httpx — `search_docs`, `search_web`, `calculator`, `wikipedia_search` (the model emits real `tool_calls`; the loop runs them in plain Python).
- **Real token-by-token streaming** — `llm_chat_stream` uses `stream=True` + SSE, yields `delta.content` live and reconstructs `delta.tool_calls` from the stream so the tool-calling loop keeps working mid-stream.
- **ChatGPT-style get-started screen** — centered greeting + centered text input (＋ popover for files), then an instant flip to the bottom chat input after the first message.
- **Persistent per-user Library** — every uploaded file is saved to disk (`library/<user>/`); a dedicated Library page lists them all with preview + delete (with a confirm dialog).
- **Sidebar** — 🌐 NexusAsk header, Library button, ➕ New Conversation, conversation history (rename / delete via ⋮), 🗑️ Clear All, user info + Logout.
- **Long-term memory** — LLM-extracted durable facts, stored per-user (JSON), injected into the agent's system prompt so the agent remembers you across conversations.
- **Per-conversation checkpoints** — conversations are saved (messages + truncated chunks) and can be reviewed/resumed.
- **Semantic cache** — local `paraphrase-multilingual-MiniLM-L12-v2` embeddings + cosine similarity; a repeated/paraphrased question hits the cache (no LLM call).
- **Safety guard + conditional disclaimer** — sensitive words short-circuit the agent; a disclaimer is appended only to web/Wikipedia answers.
- **LangSmith tracing** — `@traceable` bridges the raw-httpx gap.
- **Confirm dialogs** (`@st.dialog`) — delete file / clear history / logout.
- **File preview** — PDF / docx / pptx / xlsx / txt / md / csv.

## Crucial trade-offs & decisions

These are the non-obvious design choices that shape the app — each is deliberate.

### 1. Pinned legacy LangChain 0.1.20 (no LangGraph)
The stack is intentionally pinned to `langchain==0.1.20` / `langchain-core==0.1.53`. LangGraph is **incompatible** with the 0.1.x core, so the agent loop is **plain Python + native function-calling** (a hand-rolled `for step in range(max_steps)` loop), not a graph runtime. **Trade-off:** no graph-style orchestration; the loop is simple + debuggable, but a future LangChain upgrade would require migrating to LangGraph.

### 2. Real streaming skips faithfulness self-correction
The streaming path (`agentic_answer_stream`) **skips** the faithfulness self-correction that the non-streaming path (`agentic_answer`) has. Self-correction needs the **full** answer to run the embedding-similarity check, which conflicts with streaming tokens live. **Trade-off:** the streamed answer is final (no re-grounding); live streaming won out over the (rare) self-check.

### 3. Streaming may surface the model's "narration"
When the model calls a tool, it sometimes emits narration content (e.g. "Let me search…") **alongside** `tool_calls`. With live streaming this is yielded as it arrives. **Trade-off:** document Q&A (no tools) streams cleanly; web-search questions may show narration before the final answer. (Could be hidden with a per-step buffer, at the cost of the live token feel.)

### 4. Lazy title generation (instant new-conversation click)
A new conversation saves a **temp title** (first question, truncated to 24 chars + "…") + `title_is_final=False` — no LLM call on click. The real title is generated by a **background thread** when the sidebar next renders the conversation. **Trade-off:** the title is temp briefly, then "silently" upgrades on the next rerun. This (plus backgrounding `extract_memory`) makes "New Conversation" instant instead of ~2-20s.

### 5. Background memory extraction (eventually consistent)
`memory.extract_memory` runs in a **fire-and-forget background thread** on "New Conversation" + logout, so it doesn't block the click. **Trade-off:** memory is eventually consistent — the very next question might not yet see the just-extracted facts; it's up-to-date by the following question.

### 6. Cache-hit streams with a small delay
A cache hit yields the cached answer in 3-char chunks with a 0.01s pause (not instantly), so it *feels* like a stream. **Trade-off:** cached answers aren't instant; they stream briefly (~0.7s for 200 chars) for visual consistency with real streams.

### 7. Tool_calls parsed from the SSE stream
`llm_chat_stream` parses `delta.tool_calls` (accumulated by index: id / function.name / function.arguments) to drive the tool-calling loop mid-stream. **Trade-off:** depends on the DeepSeek cpolar proxy's streaming `tool_calls` format matching the OpenAI SSE delta schema (verified — it does).

### 8. `@traceable` bridges the httpx tracing gap
`LANGCHAIN_TRACING_V2` only traces langchain calls, not raw httpx. The `@traceable` decorator on `llm_chat`/tools bridges this. **Trade-off:** the streaming `llm_chat_stream` is **not** `@traceable` (generators + tracing don't mix cleanly), so streamed LLM calls aren't traced.

### 9. Transparent top/bottom backgrounds (CSS)
The Streamlit header + bottom container are made transparent via CSS so the purple-pink gradient shows through; chat bubbles + chat input stay white. **Trade-off:** relies on Streamlit's `data-testid` selectors (`stHeader`, `stBottom`), which could change across versions.

## Architecture

- **Pinned legacy stack:** `langchain==0.1.20`, `langchain-core==0.1.53`, `langsmith==0.1.147`.
- **LLM transport:** all chat calls go to an OpenAI-compatible endpoint (the DeepSeek cpolar proxy) over **httpx** (streaming + non-streaming).
- **Agent loop:** plain Python + native function-calling (`agentic_rag.py`). No LangGraph.
- **Storage:** JSON / file-backed (no external DB) — `conversations/`, `library/`, `memory/`.

## How it works — the agent pipeline

```
guard_input -> rewrite_query -> [tool-calling loop] -> answer -> disclaimer -> [wiki source]
```

1. **guard_input** — before-model safety: sensitive words short-circuit (refusal, no model call).
2. **rewrite_query** — LLM rewrites the question for retrieval.
3. **Tool-calling loop** — `llm_chat_stream` streams content + accumulates `tool_calls`. If `tool_calls` -> run the tool, append the result, loop. If no `tool_calls` -> the streamed content is the final answer.
4. **(stream mode)** faithfulness self-correction skipped.
5. **Disclaimer** — appended if `search_web`/`wikipedia_search` was used.
6. **`[Source: Wikipedia](url)`** — appended if `wikipedia_search` returned a URL.

### Tools

| Tool | Purpose | Source |
|------|---------|--------|
| `search_docs(query, chunks, k)` | keyword-overlap retrieval over uploaded doc chunks | local |
| `search_web(query, n)` | DuckDuckGo web search | `duckduckgo-search` |
| `calculator(expression)` | safe math evaluation (sandboxed) | stdlib `math` |
| `wikipedia_search(query, sentences)` | Wikipedia summary + page URL | `wikipedia` |

## Streaming

- **`llm_chat_stream(messages, tools, _out)`** — httpx `stream=True` + SSE; yields `delta.content`; accumulates `delta.tool_calls` into `_out`.
- **`agentic_answer_stream(...)`** — generator; drives the loop; yields the final answer token-by-token; appends disclaimer/wiki.
- **`agentic_answer_cached(...)`** — generator; cache hit -> chunked stream; cache miss -> real stream.
- The UI consumes it with `st.write_stream(...)`, accumulating tokens into the saved assistant message + the `~N tokens` caption. A one-line `st.empty()` status shows "🤖 Thinking…" immediately + step labels (rewrite/tool/stream) live, then is cleared.

## Long-term memory

- **`extract_memory(email, messages)`** — LLM extracts 1-5 durable facts per conversation (per-user JSON, cap 30). Runs in a background thread on new-conversation/logout.
- **`load_memory` / `format_memory_prompt`** — facts injected into the agent's system prompt under `## Remembered about this user`.

## Semantic cache

The question is embedded (local MiniLM); cosine vs cached questions. If `>= 0.9`, the cached answer is returned (chunked stream, no LLM call). Else cache miss -> agentic stream + cache the result.
